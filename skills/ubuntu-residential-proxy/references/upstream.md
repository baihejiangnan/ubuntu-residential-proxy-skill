完整原始文件在 `vendor/reality-setup/`；逐文件校验值在 `vendor/manifest.json`。通过 A（克隆）→ B（不带 .git 的内容副本）→ Skill vendor 方式收录。Git blob 原始 LF 内容保持一致；本仓库另起 Git 历史。移除上游 Git 历史不等于移除作者署名或许可证。

`scripts/install.py` 只在服务器的受保护临时目录生成适配版本：

1. 仅允许全新 Ubuntu，拒绝已有部署和占用的 443，安装期间持有独占锁。
2. 移除重新安装/删除旧面板的分支，避免 Agent 意外复用安装器破坏现有节点。
3. 将固定面板密码替换为运行时随机密码；面板仍只监听回环。
4. `read` 使用 `IFS= read -r`，保留用户名和密码里的反斜杠、首尾空格。
5. 兼容面板 API 返回的字符串/对象形态。
6. 在受保护日志捕获安装输出；安装末尾额外验证双节点、自测、住宅出口比对及全部导出文件。上游允许跳过 Hysteria2，适配器不把这种状态算作完整成功。

这些变更在适配器中有固定锚点和测试；上游字节校验失败或锚点变化时停止，不静默运行新版本。

上游仍从官方地址获取 3x-ui v3.9.0 安装脚本及其依赖，Ubuntu 软件包也需联网。上游每周检查 Xray 更新并执行有限自测/回滚，不能将其描述为“所有依赖永久固定”或“完全离线”。本 Skill 的首次部署不会主动改动用户默认分流集合。

后续更新上游应下载明确标签，重新比较变更、更新快照和 manifest、测试适配锚点及导出流程，再发新版本；不要让生产部署自动跟随 main。
